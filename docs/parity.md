# Feature and fidelity status

## Baseline and meaning

The target is **Windows Phone 8.1 Update (2014, often called Update 1)**. Live folders belong to this target; Windows 10 Mobile's later navigation and visual treatment do not. Shared behavior from the 2015 Microsoft user guide is used where it also applies to 8.1 Update. Primary references and detailed original requirements are in [reference.md](reference.md).

**This repository does not claim 100% visual or feature parity.** An application can reproduce the shell and useful workflows, but it does not acquire the original operating system's cellular stack, device-management privileges, application runtime or retired cloud services. The table below describes code that is present, rather than asserting that every behavior has passed testing on every browser and physical device.

## App and platform expansion

The current implementation adds independent **Podcasts** and **Wallet** packages, bringing the default composition to **27 registered apps** in a **46-package workspace**. Existing app crates gain Office history/typed formulas, OneNote organization/checklists, media playlists/queues, photo albums, saved-place directions and persistent multi-city forecasts. Shared implementations stay in domain, state, controls, SDK and support crates rather than adding app-specific dispatch to the shell.

The reusable platform work adds bounded cancellable public-HTTPS tasks, playback-event subscribers that retain source/document ownership outside the active route, and native OS media sessions. Scope-owned offline caches and waiting-worker updates keep a running page on one app version. [SDK contracts](sdk.md) and [host boundaries](host-integration.md) document the limits and actual provider behavior.

Verification for this expansion covers typed formulas and XLSX caches, history invalidation, atomic note/media mutations, playlist/album storage, queue ownership, feed and wallet validation, HTTP limits/cancellation, native media protocol handling and offline-update lifecycle. Rendered tests additionally exercise the native app commands, persistence, reload and narrow-screen controls. Revision-specific integrated build results will be recorded below after the complete release gate.

## SDK, games and native adapter implementation

Source [`d8f3d03`](https://github.com/FerroUI/WindowsPhone/commit/d8f3d03c8b6604e12361aebcd9ecd7430e9f9bd1) separates `phone-sdk`, `phone-system`, the default `phone-ui` composition facade and **33 app/editor/support/example crates** in a **44-package workspace**. All 23 built-in entry points and both games use manifest registration; Word, Excel and PowerPoint are separate editor crates reached through Office. App implementations and private state no longer live in `phone-ui`. A dependency audit confirms that SDK/system crates have no app dependencies and app crates have no system/composition dependencies. The SDK supplies typed transient state, bounded JSON storage, lifecycle/data activation, custom live tiles, cancellable file tasks, a compiled starter and scaffold generator. See [SDK documentation](sdk.md) and [architecture](architecture.md).

Tic tac toe and Minesweeper exercise discovery, gameplay, persistent app data, Start pinning and Store enable/disable through those contracts. They are working games for this recreation, without a claim that Microsoft bundled these implementations or that they restore Xbox Live. OneNote uses the typed SDK chooser for bounded UTF-8 TXT/Markdown imports. Native media/camera providers, foreground alarm audio, notification adapters, one-shot location/weather and attachment copies use the shared host boundary. [Native prerequisites](../crates/phone-desktop/platform/README.md) explain provider availability, Linux dependencies and macOS packaging.

### Extraction checkpoint and practical limits

The [local extraction record](verification/d8f3d03-local.json) for `d8f3d03` passed **179 Rust tests** across every non-browser workspace package and **25 JavaScript tests**. The [initial browser record](verification/d8f3d03-results.json) passed 53 groups/104 captures before the added symbol-pixel checks. Local native media/camera compilation used unavailable-provider bridges because the development dependencies were absent; the subsequent native CI compiles the actual platform bridges. These totals belong to their named revisions, and overlapping CI/local executions are not added into a synthetic test total.

Apps remain trusted statically linked Rust: there is no XAP/APPX loader, original Windows Runtime ABI, package marketplace, process sandbox, original tombstoning or background-agent system. Extension switcher cards currently use metadata rather than captured pages. ## Service authenticity

Microsoft's [Windows Phone 8.1 lifecycle notice](https://learn.microsoft.com/en-us/lifecycle/announcements/windows-phone-8-1-end-of-support) and [Store package/update lifecycle notice](https://blogs.windows.com/windowsdeveloper/2018/08/20/important-dates-regarding-apps-with-windows-phone-8-x-and-earlier-and-windows-8-8-1-packages-submitted-to-microsoft-store/) establish the legacy platform's discontinued support and distribution constraints. Recreating a sign-in screen would not restore those services, so the app does not claim that local sample data or included-app management is an authenticated legacy account.

Modern integrations can be added behind the existing host-service boundary. They need their own provider configuration, explicit account flows and truthful delivery/synchronization states; they must not silently masquerade as restored original Windows Phone services.
